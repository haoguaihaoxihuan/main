蜀道安全助手 RAG 优化方案，分两条主线讲：优化路径与测试集策略。

---

## 一、RAG 优化路径

按见效快慢和改动量从小到大，分五个阶段递进：

### 阶段1：检索基础加固（收益高、成本低）

**现状问题**：当前 AI 助手直接查 `knowledge_docs` 表做关键词匹配，召回精度有限。

| 优化点    | 动作                                                          | 预期收益         |
| ------ | ----------------------------------------------------------- | ------------ |
| 混合检索   | 关键字 BM25 + 向量相似度双路召回后 RRF 融合排序                              | 召回率提升 20-30% |
| 文档切片优化 | 按章节/条款拆分（安全规范天然有层级结构），单 chunk 控制在 300-500 token，重叠 50 token | 避免答案截断，减少幻觉  |
| 元数据过滤  | 切片时保留 `{文档类型, 适用范围, 发布年份}`，检索时先过滤后召回                        | 缩小检索范围，提升精度  |

### 阶段2：检索质量提升

| 优化点      | 动作                                                           |
| -------- | ------------------------------------------------------------ |
| Query 改写 | 用户问"脚手架多高要验收" → LLM 改写为"建筑施工脚手架搭设验收高度标准"，再检索                 |
| 多轮上下文    | 对话历史中提取关键实体，拼入当前 query；如用户先问"高空作业"，再问"安全带要求"，拼接为"高空作业 安全带要求" |
| 重排序      | 粗召回 Top20 → 用 bge-reranker-v2-m3 精排取 Top5                    |

### 阶段3：生成质量提升

| 优化点        | 动作                                              |
| ---------- | ----------------------------------------------- |
| Prompt 模板化 | 按场景分模板：法规查询用引用格式模板、隐患报告用结构化模板、培训大纲用章节式模板        |
| 引用溯源       | Prompt 中要求必须标注引用自哪个文档第几条，前端渲染为可点击链接             |
| 拒答兜底       | 当检索 Top1 相似度低于阈值（如 0.6）时，不强行生成，回复"未在知识库中找到相关依据" |

### 阶段4：知识库持续优化

| 优化点    | 动作                                               |
| ------ | ------------------------------------------------ |
| 增量入库   | 政策文件更新时，先查重（相似度 >0.95 视为重复），仅入库新内容               |
| 过期标记   | `knowledge_docs` 表增加 `expire_date` 字段，废止的规范降权或排除 |
| 用户反馈闭环 | 对话记录中搜集"不满意"信号，自动标记对应 chunk 质量差，定期人工复核           |

### 阶段5：高级能力（按需）

| 方向          | 说明                                                  |
| ----------- | --------------------------------------------------- |
| 多模态 RAG     | 隐患图片识别时，将图转化为文本描述 + 嵌入向量，同时检索图文知识库                  |
| Agentic RAG | 复杂问题自动拆解为多步（先查规范 → 再查案例 → 综合回答），适合"根据XX规范分析XX事故"类问题 |
| Graph RAG   | 构建安全法规知识图谱（法规→条款→处罚→案例），支持多跳推理式问答                   |

## 二、测试集收集策略

核心原则：**真实场景 > 人工构造，分层覆盖 > 随机抽样**。

### 2.1 来源渠道（按优先级）

| 优先级 | 来源                                    | 收集方式                            | 数量预估              |
| --- | ------------------------------------- | ------------------------------- | ----------------- |
| P0  | 后端 `conversations` + `messages` 表已有对话 | 导出 user 消息，脱敏后人工标注 ground truth | 按对话量，预计 200-500 条 |
| P0  | PRD 中各模块功能描述 + 安全法规原文                 | 从文档中提取 FAQ 形式 Q&A 对             | 80-120 条          |
| P1  | 安全培训模块生成的培训大纲 + 考题                    | 题干作为 query，对应章节内容作为答案           | 100-200 条         |
| P1  | 百度/Google 搜索结果中"蜀道集团 安全管理"相关公开资料问答    | 爬取后人工筛选标注                       | 50-100 条          |
| P2  | 邀请安全员试用后，导出对话日志                       | 真实用户意图，最贴近生产                    | 视试用周期而定           |

### 2.2 分层设计

每类场景至少覆盖 30 条以上：

| 场景分类   | 示例 query                | 预期答案特征              |
| ------ | ----------------------- | ------------------- |
| 法规查询   | "高处作业安全带使用规范"           | 精确引用法规编号 + 条款原文     |
| 事故案例分析 | "塔吊倒塌常见原因"              | 多文档综合，含统计数据和案例      |
| 施工操作指引 | "脚手架连墙件设置间距要求"          | 数值型答案，含 2步/3跨 等具体参数 |
| 隐患识别描述 | "基坑边坡出现裂缝多大需要停工"        | 条件判断型，多因素综合         |
| 培训材料生成 | "劳务人员入场安全培训大纲"          | 结构化输出，章节式           |
| 开放式对比  | "住建部37号令与蜀道内部红线规定有什么区别" | 多文档对比，表格化           |
| 边界/拒答  | "比特币挖矿安全规范"             | 应拒答，测试阈值兜底          |

### 2.3 标注规范

| 字段            | 说明                                    |
| ------------- | ------------------------------------- |
| `query`       | 用户原始问题                                |
| `contexts`    | 检索应返回的理想文档 chunk 列表（至少 1 条，最多 5 条）    |
| `answer`      | 标准答案全文                                |
| `source_type` | `single_doc` / `multi_doc` / `reject` |
| `difficulty`  | `easy` / `medium` / `hard`            |

### 2.4 评测指标

| 指标              | 计算方式                    | 目标值   |
| --------------- | ----------------------- | ----- |
| 召回率 Recall@5    | Top5 中是否含标注 contexts    | >0.90 |
| 精确率 Precision@5 | Top5 中有几条在标注 contexts 中 | >0.70 |
| 答案准确率           | LLM 输出与 answer 的语义一致性   | >0.85 |
| 拒答准确率           | 对 reject 类 query 是否触发拒答 | >0.95 |
| 引用准确率           | 引用条款编号是否与 contexts 一致   | >0.90 |

---

**建议落地节奏**：先跑阶段1（混合检索 + chunk 优化），同步按 P0 渠道攒测试集，跑一轮 baseline 后再逐阶段迭代。阶段1纯工程改动，后端改动量约 2-3 天。
